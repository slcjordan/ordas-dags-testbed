# ordas-dags-testbed

Stands in for a customer's Airflow repository. ORDAS opens pull requests here
as the `ordas-dev` GitHub App, and what this repository's CI says about them is
Gate C.

Nothing here is written by hand. Every file under `dags/`, `tests/`, `config/`
and `evidence/` arrives in a pull request generated by `cmd/ordaspr` in
[slcjordan/ordas](https://github.com/slcjordan/ordas).

## Why it exists separately

Gate C asks whether a generated DAG survives a CI that is not ours. A test
suite in the generator's own repository cannot answer that: it runs the linter
we chose, at the version we pinned, against a stub of Airflow we wrote. The
point of this repository is that its checks were configured without reference
to what the generator happens to emit.

So the checks here should be ordinary rather than accommodating. If a generated
file fails them, the generator is what should change.

## Reading a pull request from ORDAS

Each pull request carries, per segment:

| path | what it is |
|---|---|
| `dags/*.py` | the Airflow DAG — one task, no branch, no loop, no error handling |
| `tests/test_*.py` | asserts the DAG imports and declares what it claims to |
| `config/*.yaml` | a record of what the DAG was generated from; nothing reads it at run time |
| `evidence/*.json` | what was measured, and what was excluded from the measurement |

Read the evidence block first. A pull request whose title says `[unmeasured]`
is one where no shadow window was supplied, which means an absent agreement
rate rather than a clean one. That distinction is the point.

Editing a generated file is not forbidden, it is measured. `ORDAS_SOURCE_SHA256`
in each DAG hashes the inputs it was generated from and the evidence block
hashes the file's contents, so a hand-edit moves the second and leaves the
first. A hand-edit you tell us about is worth more than a clean regeneration
that hides what had to change.
